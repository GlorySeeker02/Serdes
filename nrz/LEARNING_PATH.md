## 1. 学习顺序总览

顺序不是按"模块在链路里的位置"，而是按**依赖关系**：
先有波形和眼图的概念，才能谈损耗；先量化了 ISI，才能谈均衡；
先归一化幅度，自适应才有意义；最后才是系统级预算。

| Stage | 一句话问题 | 主要代码 | 实验 |
|---|---|---|---|
| 1 | 一个 UI / 一张眼图到底是什么？ | `signals.py` | `lab01_waveform.py` |
| 2 | 信道把眼图怎么了？怎么量化？ | `channel.py` | `lab02_channel_isi.py` |
| 3 | 在发送端能怎么补救？ | `tx.py` | `lab03_tx_ffe.py` |
| 4 | 接收端的模拟均衡怎么做？ | `rx.py: design_ctle` | `lab04_ctle.py` |
| 5 | 为什么必须先做幅度归一化？ | `rx.py: front_end` | `lab05_agc.py` |
| 6 | 采样时钟从哪来？ | `rx.py: run`（CDR 部分） | `lab06_cdr.py` |

> **信道制造了拖尾（ISI）→ 均衡器想办法把这串拖尾系数抹平 → 但每个均衡手段都有代价

## Stage 1 · 时间基、PRBS、NRZ、眼图

### 目标
把「比特 → 波形 → 眼图」这条链走通，建立两个直觉：UI 是什么，眼图是什么。

### 核心概念（可抄进笔记）

- **UI** = 1 个比特占的时间 = 1/数据率。10 Gbps → 100 ps。
- 模型里每 UI 采 32 点 → `fs = 320 GS/s`，`dt = 3.125 ps`。
  这 32 点不是为了"精度"，而是为了**让采样相位可以连续调节**（CDR 调的就是这个小数相位）。
- **奈奎斯特频率 = 数据率 / 2 = 5 GHz**。1010 图案就是 5 GHz 正弦，
  是 NRZ 判决必须能分辨的最快变化，所以信道指标几乎总标在 5 GHz。
- **眼图 = 把长波形按 UI 切片，全部叠画**。每一列的样本直方图 → 该相位处的垂直眼高。
  曲线的**高度** = 电压余量，**宽度** = 时间余量。
- **PRBS7** 的游程分布是 32/16/8/4/2/1/1（每周期 64 个游程），
  最长 7 连 0 → 激励里有 ~1.4 GHz 的低频成分。这是它优于 1010 图案的原因。

### 代码地图
- `serdes_model/signals.py:26` `prbs_bits` —— LFSR，抽头表在 `_POLY_TAPS`
- `serdes_model/signals.py:50` `symbols_to_nrz` —— 升余弦边沿，`rise_ui` 控制过渡宽度（实际过渡 = **2×rise_ui** UI）
- `serdes_model/analysis.py:40` `eye_segments` / `analysis.py:53` `eye_hist2d` —— 折叠与直方图
- 实验里 `eye_profile()` 把"眼图的数学定义"逐相位算出来（`lab/common.py`）

### 跑什么

```powershell
conda run -n base python nrz/lab/lab01_waveform.py
```

### 实测基线（10 Gbps 默认参数）

| 参数 | 值 |
|---|---|
| UI / dt / fs / Nyq | 100 ps / 3.125 ps / 320 GS/s / 5 GHz |
| 波形总长 | 4096 bit × 32 = 131072 点 |
| PRBS7 每周期游程数 | 64（长 1:32, 2:16, 3:8, 4:4, 5:2, 6:1, 7:1） |

**1.4 上升时间：吃掉的是眼宽，不是眼高**

| nrz_rise_ui | 过渡宽度 [UI] | 垂直眼高 [V] | 水平眼宽 [UI] |
|---|---|---|---|
| 0.00 | 0.00 | 1.000 | 0.969 |
| 0.20 | 0.40 | 1.000 | 0.906 |
| 0.50 | 1.00 | 1.000 | 0.750 |

眼高从头到尾是 1.000 不动。**「边沿慢 → 眼高小」是常见误解。**

**1.4b 换成有拖尾的一阶 RC，眼高才真的塌**

| tau [UI] | 等效 -3dB 带宽 [GHz] | 垂直眼高 [V] |
|---|---|---|
| 0.05 | 31.8 | 1.000 |
| 0.20 | 8.0 | 1.000 |
| 0.35 | 4.5 | 0.887 |
| 0.50 | 3.2 | 0.490 |
| 0.80 | 2.0 | 0.106 |

**结论：让眼图闭合的是"记忆/拖尾"（带宽），不是"坡度"（上升时间）。**

### 动手改（改完预测一下再看结果）

1. `nrz_rise_ui` 改成 `1.5` —— 眼高会崩，但原因是模型的过渡互相覆盖，已经没有物理意义了（说明"边沿"这条路走不到底）。
2. `prbs_order` 改成 `15` —— 最长游程变 32767，低频更狠；但 4096 bit 内几乎没机会出现长游程，**看不出区别**（这也是为什么测低频 droop 要够长的码型）。
3. 把 `samples_per_ui` 改成 `8` —— 所有事都还能跑，但相位分辨率只剩 1/8 UI，实验 6 的浴盆曲线会变成锯齿状。

### 常见误解
- ❌「眼图是示波器的功能」→ ✅ 眼图就是折叠+直方图，`eye_hist2d` 20 行代码。
- ❌「上升时间越慢眼高越小」→ ✅ 先慢的是眼宽。
- ❌「采样率越高越准」→ ✅ 采样率在这里是"相位分辨率"，不是精度。

### 自测
1. 一个 UI 里为什么要 32 个采样点，而不是 2 个？
2. 10 Gbps NRZ 的频谱主瓣到 10 GHz，为什么指标标在 5 GHz？
3. 波形的过渡宽度是 `rise_ui` 还是 `2×rise_ui`？

## Stage 2 · 有损信道与 ISI

### 目标
把"频域损耗"翻译成"时域拖尾"，再把拖尾量化成一串 ISI 系数 `h[k]`。

### 核心概念

- 损耗模型：`L(f) = L_nyq · [ skin·√(f/f_nyq) + (1-skin)·(f/f_nyq) ]`
  —— 趋肤 ∝√f，介质 ∝f，`skin_ratio` 是配比。
- **频域幅度衰减 ⇔ 时域脉冲拖尾**，是同一件事的两面。
- 归一化后的 `h[k]` 就是教科书的 ISI 系数：
  - `h[k<0]` 前游标（pre-cursor）→ 只能用 **TX FFE / CTLE** 处理
  - `h[k>0]` 后游标（post-cursor）→ 用 **DFE** 抵消
  - 均衡的全部目标：把 `h` 逼近 `[...,0,0,1,0,0,...]`
- **ISI 总和 > 1 就意味着眼必然闭合**：最坏码型能把采样点推到门限另一侧。

### 代码地图
- `channel.py:18` `channel_transfer` —— 损耗公式（零相位！只有幅度，没有群时延）
- `channel.py:34` `apply_channel` —— FFT 乘上 H(f)，再加串扰/噪声
- `lab/common.py: pulse_cursors` —— 用**阶跃响应差分**算 `h[k]`（比直接发孤立脉冲稳健）

### 跑什么

```powershell
conda run -n base python nrz/lab/lab02_channel_isi.py
```

### 实测基线

**2.2 裸判决（无 VGA/CTLE/AGC/DFE，固定相位 0，无 TX FFE）**

| 损耗@Nyq [dB] | 垂直眼高 [V] | 水平眼宽 [UI] | 相对 0dB | BER |
|---|---|---|---|---|
| 0 | 1.958 | 0.844 | 100% | 0 |
| 6 | 0.973 | 0.719 | 50% | 0 |
| 12 | 0.340 | 0.531 | 17% | 0 |
| 16 | 0.079 | 0.281 | 4% | 7.9e-3 |
| 20 | -0.096 | 0.000 | -5% | 6.6e-2 |
| 26 | -0.251 | 0.000 | -13% | 1.5e-1 |
| 32 | -0.330 | 0.000 | -17% | 1.7e-1 |

注意 **6 dB 眼高正好掉一半**：眼高按 `10^(-L/20)` 缩，不是按 dB 线性缩。

**2.2b 误码不是随机的（32 dB 时）**

| 3 比特邻域 | 占比 | 该类 BER |
|---|---|---|
| 111 / 000（长游程内部） | 24.6% | **0.000** |

错的全是"必须靠高频才能分辨"的孤立比特。

**2.3 20 dB 信道的 ISI 系数**

| 偏移 | h[k] |
|---|---|
| -2 | +0.155 |
| -1 | +0.404 |
| **0** | **+1.000**（原始值 0.306 → 单比特只能爬到阶跃的 31%） |

**2.3c 交叉验证（这个技巧很值得记）**

| 偏移 | 回归法（从真实码流最小二乘） | 脉冲法（从阶跃响应） |

| +2 | +0.1539 | +0.1556 |

### 动手改
1. `channel_skin_db_ratio` 从 0.5 改成 1.0（纯 √f）—— 同样 20 dB，眼图会**好一点**：
   因为 10 GHz 处 √f 只多 8.3 dB，而纯 f 要多 20 dB。
2. `channel_loss_db_at_nyquist` 设成 40 —— BER 会饱和在 ~0.2 而不是 0.5，想想为什么
   （提示：还是直流增益 1）。
3. 把 `pulse_cursors(..., span=8)` 改成 `span=3` —— 会低估 ISI 总和，因为拖尾被截断。

### 常见误解
- ❌「20 dB 损耗 = 幅度掉 20 倍」→ ✅ 20 dB = 10 倍幅度，但那是 Nyquist 处，不是全频段。
- ❌「BER 0.5 说明噪声很大」→ ✅ 说明判决与数据**完全不相关**（眼全闭/相位全错/环路飞了）。
- ❌「一个损耗数字就够了」→ ✅ 还要看形状（skin_ratio），低频 droop 和高频衰减是不同的病。

### 自测
1. 为什么 20 dB 时主游标只剩 31%，而长连 1 的电平几乎不变？
2. `h(-1) ≈ h(+1)` 说明这个信道有什么特点？真实信道为什么不是这样？
3. 误码为什么集中在孤立比特上？

## Stage 3 · TX FFE / 预加重

### 目标
在发送端用"已知未来比特"做频域预失真，同时压前游标和后游标。

### 核心概念

- 3-tap FFE：`y[k] = pre·a[k+1] + main·a[k] + post·a[k-1]`（符号域 FIR）
- **它不是放大信号，而是重分配频谱**：
  - 直流增益 `Σtaps < 1`（长连 1 的电平被压低）
  - 跳变摆幅 `|pre|+main+|post| > 1`（孤立比特被抬高）
  - 等价于在发送端做高通整形，正好抵消信道的低通
- **pre 抽头只能改 `h(-1)`，post 抽头只能改 `h(+1)`**，两者几乎解耦。
  因为 FFE 是线性卷积：`h_eff = conv(h_channel, taps)`
- 代价两条：**摆幅损失**（直流增益）+ **噪声放大**（AGC 增益 = 1/直流增益）。

### 代码地图
- `serdes_model/tx.py:28` `apply_ffe` —— 就是 `np.convolve(syms, taps, mode="same")`，三行
- `serdes_model/tx.py:38` `to_waveform` —— 符号流 → NRZ 波形（含边沿/抖动）
- `serdes_model/signals.py:50` `symbols_to_nrz` —— 边沿在这里生成
- `lab/common.py: pulse_cursors(tx_taps=...)` —— 把 FFE 卷到游标上，不用重发波形

### 实测基线

**3.1 默认抽头对符号流做了什么**

| tx_taps | 直流增益 Σ | 最大摆幅 | 低频损失 |
|---|---|---|---|
| (0, 1, 0) | +1.00 | 1.00 | 0 dB |
| (-0.15, 0.85, -0.2) | +0.50 | 1.20 | **-6.0 dB** |
| (-0.3, 1.0, -0.15) | +0.55 | 1.45 | -5.2 dB |

长连 1 的稳态只有 **+0.50**，孤立 1 能冲到 **+1.20** —— 这就是预加重的全部。

**3.2 游标视角（20 dB 信道）**

| tx_taps | h(-2) | h(-1) | h(+1) | h(+2) |
|---|---|---|---|---|
| (0, 1, 0) | +0.155 | +0.404 | +0.404 | +0.156 |
| (-0.15, 0.85, -0.2) | +0.077 | +0.229 | +0.169 | +0.055 |
| (-0.4, 0.85, 0) | **-0.043** | **-0.082** | +0.408 | +0.143 |
| (0, 0.85, -0.3) | +0.146 | +0.407 | +0.059 | +0.015 |

看第三行：**pre 压过头，`h(-1)` 直接反号**。均衡过度的第一个征兆就是游标翻负。

**3.3 端到端扫描（20 dB，无 DFE）**

| pre | post | AGC 后眼高 | BER |
|---|---|---|---|
| 0.00 | 0.00 | 0.070 | 2.3e-2 |
| -0.10 | -0.10 | 0.598 | 0 |
| -0.20 | -0.20 | 1.154 | 0 |
| -0.30 | -0.20 | 1.486 | 0 |

**3.4 代价（6 dB 信道 + 0.02 噪声）**

| pre/post | 直流增益 | 眼高 | 垂直厚度 | BER |
|---|---|---|---|---|
| 0/0 | 1.00 | 1.681 | 0.409 | 0 |
| -0.15/-0.10 | 0.75 | 1.754 | 0.538 | 0 |
| -0.30/-0.20 | 0.50 | 1.181 | 1.134 | 0 |
| -0.45/-0.30 | 0.25 | 0.551 | **1.776** | 0 |

AGC 把幅度拉回来了（增益 ×4），但**噪声也 ×4**，眼高反而被抹掉、厚度涨 4 倍。

### 动手改
1. 把 `main` 从 1.0 改回 0.85（默认值），重跑 3.3 —— 眼高整体下降，因为直流增益又掉了 15%。
2. `pre=-0.6` —— 看 `h(-1)` 被压成多深的负数，并观察眼图出现"过冲/双峰"。
3. 把信道改到 6 dB 而 pre 保持 -0.45 —— 眼高从 1.681 掉到 0.551（3.4 已经做了），这就是"过均衡"。

### 常见误解
- ❌「预加重就是把信号放大」→ ✅ 是**重分配**频谱，直流增益反而变小。
- ❌「抽头越负越好」→ ✅ 会有游标反号 + 摆幅/噪声的代价，存在最优点。
- ❌「FFE 能替代 DFE」→ ✅ 它对付前游标，后游标它只能"顺手"压一点，且会放大噪声。

## Stage 4 · CTLE 连续时间线性均衡

### 目标
用一个"一零两点"的模拟滤波器在 Nyquist 附近抬高频，并看清它的边界。

### 核心概念

```
H(s) = A_dc · (1 + s/wz) / ((1 + s/wp1)(1 + s/wp2)),   wp1 < wz < wp2
```
- `peaking` 越大 → `wz` 与 `wp1` 拉得越开 → 上升段越宽越高；峰值大致落在 `fz`~`fp1` 之间（第三个极点把它往右拉到 7~8 GHz）。
- 第三个极点 `wp2` 固定在 15 GHz，防止把 GHz 以上的噪声一路抬上去。
- 实现：双线性变换 `s → 2fs(1-z^-1)/(1+z^-1)` 转 IIR（`filters.py:19`），直接 II 型转置结构。
- **直流增益 = 1**，所以它不改变长连 1/0 的稳态电平（AGC 逻辑不受影响）。
- **它是因果最小相位滤波器**：压得住后游标，压不住前游标（前游标需要"预知未来"，只有 TX FFE 能办）。

### 代码地图
- `serdes_model/rx.py:30` `design_ctle` —— 由 `peaking_db`/`f_peak` 反推 `wz/wp1/wp2`，再离散化
- `serdes_model/filters.py:19` `bilinear_biquad` —— 双线性变换的系数推导（看到 `c = 2fs` 那几行）
- `serdes_model/filters.py:39` `lfilter` —— 有 scipy 用 C 实现，否则走纯 numpy 的 DF2T
- `serdes_model/rx.py:56` `front_end` —— VGA → CTLE → AGC 三步，全在这里

|---|---|---|---|

| 6 | 3.54 | 7.06 | 15.0 |
| 12 | 2.51 | 9.98 | 15.0 |

（`fz·fp1 = f_peak² = 25`，所以峰值恒在 5 GHz。）

### 动手改
1. `ctle_peak_freq_ghz` 改成 2.5 或 10 —— 峰值离开 Nyquist，收益立刻变差（说明"在哪抬"比"抬多少"更重要）。
2. `ctle_dc_gain` 改成 2 —— 全频段 +6 dB，眼高变大但 AGC 会把这点收益吃掉（因为 AGC 归一化），只有 SNR 受影响。
3. 在 4.2 里把 `channel_noise_sigma` 从 0.03 加到 0.06 —— 最优点会往小 peaking 移。

### 常见误解
- ❌「CTLE 是自适应均衡」→ ✅ 本模型是**固定** peaking；真实芯片有自适应 CTLE，但原理一样。
- ❌「peaking 越大越好」→ ✅ 抬高频 = 抬噪声/串扰。
- ❌「CTLE 能替代 TX FFE 修前游标」→ ✅ 因果滤波器改不了非因果的前游标。

## Stage 5 · AGC（幅度归一化）

> 单独给它一个 Stage，因为它是**最隐蔽的坑**：代码全对，结果全错。

### 核心概念

- AGC 用 `median(|x|)` 估计 NRZ 主抽头电平，把判决点归一化到 ±1。
- 为什么中位数够用：NRZ 大部分时间停在平顶，`|x|` 的分布有两个峰，中位数落在峰上，
  几乎不受边沿样本影响（比均值稳健）。
- **为什么必须归一化**：sign-sign LMS 的误差是 `sign(z - s)`，`s = sign(z) = ±1`。
  只有 `|z| ≈ 1` 时，`sign(z-s)` 才表示"偏大/偏小"（即 ISI 方向）。
  幅度只有 0.25 时，`z-s` 的符号恒等于 `-s`，与 ISI 无关 → 抽头被推向一个假平衡。

### 代码地图
- `serdes_model/rx.py:56` `front_end` —— 整个 AGC 就是最后 4 行：`median(|x|)` 然后除一下
- `lab/lab05_agc.py: fe_no_agc` —— 把 AGC 摘掉的最小写法（对照实验用）
- `serdes_model/rx.py:141` —— 被 AGC 保护的正是这段 sign-sign LMS

### 实测基线

**5.1 有 / 无 AGC（20 dB 信道）**

| 配置 | median\|x\| | 采样点均值 | DFE 抽头 h1..h5 | BER |
|---|---|---|---|---|
| 有 AGC | 1.000 | 1.037 | +0.11 +0.04 +0.05 +0.02 +0.05 | **0** |
| 无 AGC | 0.233 | 0.242 | **-0.21 -0.18 -0.15 -0.12 -0.09** | **5.0e-1** |

一行除法，BER 从 0 变成 0.5，抽头集体翻负。**这是本仓库 README 里记录的坑，实验 5 完整复现了它。**

**5.2 估计量对比**：`median(|x|)`=0.233，`mean(|x|)`=0.211，`median(|d|)`（只取采样点）=0.244。
三者接近，中位数够用。

**5.3 增益不变性**：`vga_gain` 从 0.2 到 5.0，AGC 后波形最大差 `6.7e-15`（数值噪声级），BER 全 0。

### 动手改
1. 把 `front_end` 里的 `np.median` 改成 `np.mean` —— 变化不大，但加了强边沿抖动/严重 droop 后会偏。
2. 把归一化搬到 DFE **之后** —— 自适应会失败（可以自己写 5 行验证）。
3. 用 `median(|x|)` 的 0.5 倍做归一化 —— 相当于幅度只有 0.5，DFE 抽头会开始偏。

### 常见误解
- ❌「AGC 只是把音量调大」→ ✅ 它决定了后面所有自适应算法是否有定义。
- ❌「AGC 放哪都行」→ ✅ 必须放在 CTLE 之后、CDR/DFE 之前，且必须真正锁定。
- ❌「AGC 改善 SNR」→ ✅ 无差别放大，SNR 不变（见 Stage 8）。

## Stage 6 · CDR 时钟数据恢复

### 目标
从数据边沿恢复采样相位，并把"锁定速度 vs 抖动"量化出来。

### 核心概念

- **每个 UI 采两个点**：边沿 `e`（off=0）和数据中心 `d`（off=0.5），相位由 `phase` 统一偏移。
- **Alexander 鉴相器**：`err = e · (s_prev − s)`
  - 只有跳变（`s_prev ≠ s`）时 `err ≠ 0`，方向表示"时钟早了还是晚了"
  - `bangbang`：边沿量化成 ±1（硬件只要一个判决器 + 异或）
  - `linear`：保留边沿模拟值（误差更平滑，抖动更小）
- **PI 环路**：`integral += ki·err`（管频率，跟踪 ppm），`phase += kp·err + integral`（管相位）
- **bang-bang 的稳态抖动是极限环**，不随噪声减小而消失，只能减小 kp。

### 代码地图
- `serdes_model/rx.py:113` `sample(k, off)` —— 唯一的"采样"入口：`(k+off+phase)·sp` 后线性插值
- `serdes_model/rx.py:124` —— 每个 UI 采 `e`（边沿）和 `d`（中心）两个点
- `serdes_model/rx.py:133` —— Alexander 鉴相 + PI 环路，共 4 行

### 实测基线

**6.1 捕获（初相位 ±0.35 UI）**

| 初相位 | 最终相位 | 锁定时间 | 稳态抖动 |
|---|---|---|---|
| -0.35 | -0.044 | 78 bit | 0.036 UI |
| 0.00 | -0.035 | 64 bit | 0.035 UI |
| +0.35 | -0.046 | 81 bit | 0.036 UI |

**6.2 环路增益的取舍**

| kp | ki | 锁定时间 | 稳态抖动 | 最终相位 |
|---|---|---|---|---|
| 1/8 | 1/128 | 21 bit | **0.150 UI** | -0.152 |
| 1/16 | 1/256 | 33 | 0.083 | -0.089 |
| 1/64 | 1/2048 | 42 | 0.036 | -0.045 |
| 1/128 | 1/4096 | 45 | 0.022 | -0.042 |
| 1/256 | 1/8192 | 60 | **0.015 UI** | -0.044 |

kp 大 → 锁得快但抖得厉害（1/8 时抖动 0.15 UI，已经快把眼宽吃光了）。

**6.3 鉴相器类型**

| cdr_type | 稳态抖动（噪声 0.01 / 0.03） |
|---|---|

### 动手改

2. `cdr_type="linear"` 且 `cdr_kp=1/8` —— 抖动仍然小，因为线性鉴相的误差幅度随偏移变小（自限幅）。
3. `cdr_initial_phase_ui = 0.45` —— 靠近眼边界起锁，捕获时间变长甚至锁到错误的稳定点（可观察）。

### 常见误解
- ❌「CDR 会找到眼图最中心」→ ✅ 它找的是"边沿能量对称"的相位，与几何中心差一点点（本模型 -0.045 UI）。
- ❌「抖动小 = 环路带宽小 = 好」→ ✅ 带宽太小就跟不上 ppm 漂移和低频抖动。
- ❌「浴盆宽度能衡量均衡效果」→ ✅ 它衡量的是**时间**余量；DFE 主要在改善**电压**余量（0.675→0.750 只是小幅）。

## Stage 7 · DFE 判决反馈均衡

### 目标
用"已经判决过的比特"抵消后游标，并看清它的软肋（错误传播）。

### 核心概念

- `z = d − Σ h_i·a_{k−i}`，`s = sign(z)`
- 反馈的是**判决**而不是模拟量 → **不放大噪声**（相对 FFE/CTLE 的最大优势）
- **sign-sign LMS**：`h_i += μ·sign(z−s)·a_{k−i}`，只需符号，硬件极省
- 收敛点不是严格 ZF（零 ISI），而是"让判决错误最少"的 MMSE 点；
  而且它只有 1 bit 误差信息，**比判决抖动还小的抽头根本学不到**
- **ISI 系数随采样相位变化** —— 比较理论值和收敛值之前，先确认相位一致

### 代码地图
- `serdes_model/rx.py:129` —— `fb = dot(taps, hist)`；`z = d - fb`；`s = sign(z)`
- `serdes_model/rx.py:141` —— sign-sign LMS 更新，两行
- `serdes_model/rx.py:146` —— 历史寄存器 `hist` 的移位（这里就是错误传播的物理位置）
- `serdes_model/rx.py:158` `deserialize` —— 判决后按字宽分组（串并转换）

### 实测基线

**7.1 收敛值 vs 理论值（30 kbit，μ=0.0005，相位 -0.045）**

| 抽头 | 理论值 | DFE 收敛值 |
|---|---|---|
| h1 | +0.061 | +0.072 |
| h2 | +0.039 | +0.039 |
| h3 | +0.041 | +0.047 |
| h4 | +0.028 | **+0.001** |
| h5 | +0.021 | **+0.003** |

h1~h3 对得上；h4/h5 学不到（小于 LMS 分辨率）。**这就是"抽头不是越多越好"的第一个证据。**

**7.2 抽头个数（26 dB 信道，噪声 0.03）**

| dfe_ntaps | z 眼高 | BER |
|---|---|---|
| 0 | +0.243 | 6.6e-3 |
| 1 | +0.428 | 5.0e-3 |
| 2 | +0.505 | 1.6e-3 |
| **3** | **+0.579** | **7.9e-4** |
| 5 | +0.491 | 1.3e-3 |
| 8 | +0.394 | 2.1e-3 |

3 个最好；5/8 反而变差（抽头抖动 + 错误传播）。

**7.3 步长 μ**

| μ | h1 | z 眼高 | BER |
|---|---|---|---|
| 0.001 | +0.069 | +1.224 | 0 |
| 0.01 | +0.110 | +1.147 | 0 |
| 0.05 | +0.150 | +0.858 | 0 |
| 0.1 | +0.300 | +0.443 | 6.6e-3 |
| 0.3 | +1.500 | **-6.9** | **3.6e-1** |

**7.4 错误传播（最精彩的一张表）**

| 损耗/噪声 | DFE | z 眼高 | 错误个数 | 相邻错误占比 |
|---|---|---|---|---|
| 26 dB / 0.03 | 关 | +0.243 | 29 | 0.00 |
| 26 dB / 0.03 | 开 | +0.491 | **6** | 0.00 |
| 26 dB / 0.05 | 开 | +0.363 | 22 | 0.00 |
| **28 dB / 0.05** | 关 | -0.222 | 143 | 0.01 |

眼还开着时 DFE 大赚；眼已经闭了，DFE 会**崩**：错误判决进历史 → 反馈错 → 更错，
LMS 还在"学"这些错误 → 抽头跑飞。相邻错误占比从 0 跳到 **0.74**，这就是 error propagation 的指纹。

### 动手改
1. `dfe_mu=0.5` —— 直接发散。
2. 把 7.4 的 28 dB 换成 30 dB —— 不开 DFE 也全错，DFE 也救不回来（说明均衡不是万能的）。
3. `dfe_train=False` 但 `dfe_ntaps=5` —— 抽头恒为 0，等价于"没有 DFE"，可用来做对照。

### 常见误解
- ❌「DFE 抽头应该等于 ISI 系数」→ ✅ 近似相等，但收敛点是 MMSE，且小抽头学不到。
- ❌「DFE 一定比没有好」→ ✅ 眼已经闭合时会灾难性恶化（7.4 最后一行）。
- ❌「DFE 能修前游标」→ ✅ 因果，只能修后游标。

## Stage 8 · 系统级余量预算

### 目标
把抖动、噪声、ISI 折算成"眼高/眼宽"两个余量，学会看整条链路的账。

### 核心概念

- **垂直余量**：眼高 vs 噪声+残余 ISI
- **水平余量**：眼宽 vs 抖动+CDR 跟踪误差
- 浴盆曲线 = 水平余量的直接读数；两端饱和到 BER 0.5 是正常现象（判决与数据无关）
- BER 对噪声是**指数**敏感（高斯尾 `Q(x) ~ exp(-x²/2)`），眼高预算常用 "12σ ↔ 1e-16"
- **AGC 把幅度拉回来 ≠ 改善 SNR**：信号和噪声一起放大

### 代码地图
- `serdes_model/analysis.py:10` `compute_ber` —— 带 ±40 UI 延迟搜索，做浴盆时要 `max_lag=0`
- `serdes_model/analysis.py:53` `eye_hist2d` —— 眼图密度直方图
- `lab/common.py: bathtub` / `width_at` —— 浴盆曲线与"BER<1e-6 的宽度"
- `lab/common.py: eye_stats` / `eye_z` —— 眼高与厚度（分位数内沿，抗极值）

### 实测基线

**8.1 浴盆**：BER<1e-6 窗口 有 DFE 0.750 UI / 无 DFE 0.675 UI（理想上限 1.0 UI）

**8.2 发送端 RJ**

## 附录 A · 可复用的 6 个调试招式

1. **先关环路，再开环路**：把 `cdr_kp=cdr_ki=0` 固定相位扫一遍，确认眼图本身没问题，
   再开 CDR；`dfe_train=False` 先看裸眼图，再开 DFE。否则你永远不知道是谁的问题。
2. **看游标，不看眼图**：眼图告诉你"多差"，`h[k]` 告诉你"差在哪"。
   `pulse_cursors()` 一行拿到全部 ISI 系数。
3. **两种独立方法交叉验证**：脉冲法（阶跃响应差分）vs 回归法（对真实码流最小二乘）。
   两者不一致，说明你的假设（线性/相位/归一化）有问题。见 2.3c。
4. **认 BER = 0.5 这个读数**：它意味着判决与数据完全不相关（眼闭/相位错/环路飞），
   而不是"噪声有点大"。
5. **看"错在哪类码型"**：把错误按 3 bit 邻域分组（2.2b）。孤立比特错 → 高频衰减；
   长游程错 → 低频 droop / AGC 漂移。这一招能直接把问题定位到频段。
6. **相位一致再比较**：ISI 系数、眼高、DFE 抽头都随采样相位变化。
   比两个数之前先确认相位相同（`pulse_cursors(..., phase=...)`）。

## 附录 C · 我在这个仓库里改过的两处代码

为了让实验说话算数，改了两个地方（都有独立理由，不影响原测试）：

1. **`channel.py` 的串扰种子**：原来串扰用的 `prbs_bits(nbits, 同阶数)` 和主数据**完全一样**
   （LFSR 初态相同），相加等于给主信号加了个相干副本 —— 结果"串扰"反而把眼图抬高了。

2. **`rx.py` 的 `dfe_ntaps=0`**：原来 `hist` 是空数组，`hist[0] = s` 会 `IndexError`。
